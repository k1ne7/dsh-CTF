# 二进制、逆向与运行时

先确定文件格式、架构、位数、入口、依赖与可运行环境；哈希原始附件，在副本上实验。
区分静态可见逻辑、实际执行逻辑和输入输出来验证的逻辑。字符串/反编译伪代码是线索，不等于执行事实。

- 校验题：定位输入到判定的依赖，留意长度、编码、有符号运算、溢出、端序与查表边界。恢复公式后先用已知样本核对，再求逆或建约束。
- 混淆/虚拟机：寻找状态、指令语义和输入相关切片；用小样本执行轨迹验证语义，避免一上来完整重写全部虚拟机。
- Pwn：把可控输入、实际内存破坏/逻辑缺陷、利用原语和环境限制分开证明。一次崩溃不是完整利用；本地与远端的加载器、libc、保护与交互时序可能不同。
- 动态方法：先选择能观测关键未知的断点/追踪位置。符号执行、仿真和 SMT 需要正确的入口状态、系统调用模型与路径约束；工具跑不动不说明题目无解。
- 分工可沿静态数据流、动态轨迹、独立求解/利用原语切开，输出统一到同一输入输出契约。

工具按已安装环境选择。没有 Linux 运行环境/所需调试器时先做可行的静态分析并说明阻塞；不要擅自安装系统或把修改提示文字当作绕过真实校验。
