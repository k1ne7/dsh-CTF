# POP 链：候选生成与运行验证

先读本题实际源码和 PHP 版本信息；知识库已有 PHP 反序列化资料，遇到具体未知再检索对应章节，不通读全文。

## 建立最小约束模型

识别反序列化入口及选项、可实例化类、入口触发方式和目标敏感操作。对相关类仅提取：
属性名与可见性、默认值/类型、魔术方法、可调用位置、关键分支与可控程度。
区分可控属性、运行后被覆盖的值、严格比较、访问权限和必须满足的对象接口。

按实际语义写调用边，例如析构中对象转换为字符串、属性访问进入 getter、对象被当作 callable 调用。
不要因为“类里存在魔术方法”就假定一定触发。结构较复杂时用 `ctf_chain` 找入口到目标的短路径；
输出只是候选，仍要检查每条边条件与副作用。若短路径受阻，修改已证伪的边后重新分析，不默认穷举全文。

## 尽早运行，而不是一次想完

现有 PHP 环境可用时，在独立副本构造最小实验：保留真实分支条件，对关键边加入可观测标记，敏感操作替换为记录器。
用同一入口和触发方式验证候选路径；诊断副本成功后，仍需用原始逻辑/题目服务验证最终结果。
没有合适运行时时，明确将运行时语义标为未验证，不擅自安装操作系统或假装执行过。

对象构造优先使用实际运行时的序列化函数，核对字节长度、可见性对应的属性键、编码/传输层和版本差异。
避免跨 PowerShell/Python/PHP 多层引号拼接，参数用文件或 argv 计划传递。

对失败只定位第一条未满足的边：类型、可见性、触发时机、参数个数、被覆盖属性、异常与析构顺序等。
修正对应约束并复测，而不是不加依据地换一条完整链。

并行分工适合“候选链构造”与“独立约束/反例检查”，主 Agent 保持主线；纯串行的单链不硬拆为多个等待阶段。
最终验证区分候选构造、诊断轨迹、原逻辑执行和平台接受。保留首个跑通脚本，避免整理阶段重复利用。
