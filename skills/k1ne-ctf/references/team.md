# 原生 Agent Teams 协作

先看当前工具列表，禁止凭本文件假设工具存在。新宿主有 `spawn_teammate`、`send_message`、`list_agents`、`wait_agent`、`interrupt_agent` 与 `team_task_*`；只有 Lead 创建/中断成员。没有 Team 时使用实际可用 workflow；没有并行工具就直接解题。

## 分工决策

初步证据获取后、进入长链探索前，Lead 主动检查是否有有用的独立未知或证据复核。存在且工具/槽位可用时，应及时派给队友，主线继续，而不是一直等到卡住。短任务或真正串行的依赖链继续单人，不为使用多Agent而制造任务。宿主调用失败时先处理真实原因，不原样反复派单。

不按题型固定建全专家组。将「不同假设」「不同观测手段」「独立子问题」拆开；同一条串行依赖链不要假装并行。
新解题任务由 Lead 主动按独立工作量选择队友数量，最多 4 个子 Agent，且服从宿主剩余槽位。
不固定一个、不默认开满四个，不修改全局上限；主线与派单同步推进，不先让所有人查一遍知识库。
优先复用已存在且合适的成员，不为同一职责不断创建新名字；宿主可能永久保留成员名与数量占用。

## 派单包

给新成员的信息应足以独立行动：
- 题目目标、授权范围、题目工作区与原始文件路径/摘要；
- 已确认事实及证据位置，哪些只是主 Agent 的猜测；
- 当前要检验的单一问题、既有失败与复现方式；
- 专属产物目录（如 `exp/worker-a/`）、不能修改的共享资源；
- 期待返回的结果：结论、证据、可运行脚本、反例/卡点、下一步。

需要独立观点时 fresh；依赖大量已完成分析时才 fork。不要给所有人主 Agent 的未经验证结论以制造虚假共识。

## 执行与合并

用原生任务板认领，按原生 schema 提交 revision；陈旧更新失败就重读，不强行覆盖。writeScopes 只提示冲突，不锁文件。
每人写独立目录；共享服务状态、浏览器账号、断点与调试端口由单一成员负责。不要并行重置题目实例。
主 Agent 可同时做独立实验；重要新证据立即发给依赖它的成员，发现分支前提被反驳则停止无效工作。
`send_message` 成功只是收件；`inactive` 只是没有运行中的回合。由结果与证据判断完成。
需要等待时用原生 wait，不连续轮询。中断不等于释放任务，检查板上 owner 和状态并按真实情况处理。

合并时解决证据冲突：优先最小可复现实验，而不是模型投票。适时用本地实验助手保存负结果；不要每发一次消息就写数据库。
