# Web、协议与状态

以题目源码和服务的实际请求/响应为共同证据。先复现正常流程，明确身份、会话、数据流、路由与信任边界，再构造最小差异请求。

- 记录必要的 method/path、状态码、关键响应、重定向与时间；不要只截取一个成功提示。
- 区分客户端展示、服务端校验、代理行为和缓存结果；源码与部署可能不一致，用请求验证。
- 有源码时沿可控输入到关键操作追踪；没有源码时用低噪声的可区分实验推导行为，不上来全量扫描。
- 解析差异需要验证每一层实际解析的字节；认证/授权缺陷要区分「能看到页面」与「确实读取目标数据」。
- 多阶段题明确前一步产出的状态/凭证如何被下一步使用，避免重复获取已失效 token。
- 浏览器、HTTP 客户端和 MCP 的 Cookie 状态可能不同；先确认正在操作哪个会话，不把 Cookie 写进公开台账或外传。

并行工作适合独立源码路径与无状态实验；同一账号写操作、实例重置、验证码与浏览器会话由单一成员协调。遇到需要真人完成的登录挑战请用户操作已有浏览器，不假装绕过成功。
